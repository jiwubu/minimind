## 1. v3 的格式与数据改动

1. **compare 倒计时状态锚**："相同"行改为 `十位: 5 = 5，相同，还剩 2 位`——针对长"相同"链上位置跟踪衰减（链尾判定翻转），给判定 token 一个可寻址状态
2. **`_close_pair` 锐化**：尾部首位即分出大小，链长精确等于 d−k（原构造尾部随机，深链样本被浅化稀释，偏置被抵消大半）
3. **k 分布偏置**：等长接近 k 向 2~3 偏置（1/2/2/3/3）；前导零 k≥5 以 40% 概率强制（实测短板补量）

## 3. 统一根因：近等值比较判定翻转

四个非满分档（负数接近 95.4、前导零 88.0、长串答案 99.3、个别等长 8 位）的错例签名完全一致：

```
比较行符号 token 写反（如 十位: 4 > 6，实为 4 < 6）
  → 交换状态行忠实执行错误判断（"不交换"）
  → 对 小-大 直接跑借位（借位演算本身全对）
  → 最高位借位无处可借被丢弃 → 10 的补码
  → 产物两种形态：999xxx（无符号）或 -999xxx（带符号）/ 塌缩为 0
```

典型错例（每档节选，全量错例以 `--dump` 文件为准）：

```
[负数接近] 4239 - 4246 = -7，预测 9993          （=10⁴−7）
[负数接近] 64156361 - 64156528 = -167，预测 99999833 （=10⁸−167）
[前导零] 1510 - 1505 = 5，预测 -9995             （带符号版，=−(10⁴−5)）
[前导零] 65658243 - 65658228 = 15，预测 -9999985
[长串答案] 12489618 - 12489396 = 222，预测 -99977778
[等长] 1859 - 1488 = 371，预测 -9629             （=−(10⁴−371)）
```

倒计时状态锚将 neg_close 提到 95.4（k=3 达 92），确认"位置跟踪衰减"假设部分成立；剩余失败集中在 6~8 位深链（前导零 88%），是单 epoch / 64M 的能力边界。

## 4. 除法错例的两类模式

| 模式 | 机制 | 错例 |
|---|---|---|
| A：验证断言错 | 试商后 `bc <= rem` 的多位比较写反 → 拒掉正确候选（欠商）或接受过大候选 → 减法借位链崩坏 | `718/98 → 784 <= 718` 后答案 99934（手测实拍）；`64/11 → 6 余 58`（余数 > 除数，非法） |
| B：商拷贝丢字 | 答案行从散落各步的试商数字远距离拼装，丢 0 与重复位 | `316620/5 → 632`（丢 33）；`6671/3 → 223`（丢 2） |

自纠机制本身可靠（触发时 82.6% 成功率、首候选命中 95.7%）；带余 89% 的残余是 A/B 混合，量级已可接受。

## 5. 已知限制（不再迭代，归档）

1. **近等值比较判定**：neg_close 95.4%（差 2.6pp 到 98 线）、前导零 88.0%。倒计时锚已回收大部分，剩余为深链（6~8 位）判定，是 64M / 单 epoch SFT 的能力边界
2. **带余 89%**：模式 A/B 混合残余
3. **训练范围外**：乘除 ≥5 位未训练（显式 opt-in `--mul_digits 6 --div_digits 8` 可观测，0~12%）
4. **固定输出格式**：模型始终输出完整竖式（方案 §8 已知代价），简短直答属后续增强项
