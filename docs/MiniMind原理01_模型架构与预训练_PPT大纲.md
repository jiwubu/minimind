### A2. 核心信息与叙事主线

**一句话核心信息**：
> 一次前向 = **`[2,340]` 的整数网格，穿过 8 层结构完全相同的 Block，全程保持 `[2,340,768]` 不变，只在两处膨胀**（打分阵 `[2,8,340,340]`、logits `[2,340,6400]`），最后塌缩成一个 loss 标量——而这个标量的唯一含义是"每个位置猜对它右边那个 token 的程度"。

**叙事姿态**：讲义作者，不是论文作者。每页回答听众心里的一个问题："这个框在干什么？它为什么必须存在？"——所有"为什么"都给**可验证的直接理由**（如：RoPE 只转 Q/K 因为位置只需参与打分不需参与内容传递；残差是虚线因为子层输出≈0 时信息要能无损通过）。

**结构**：五段旅程，按数据流动顺序：

```
第一段  看图   这张架构图要怎么看（三栏：左流水线 / 中 Layer k / 右 GQA+FFN）
第二段  入口   ① Tokenizer 文本→id   →   ② Embedding id→向量   →   RoPE 表备好
第三段  核心   ③ Layer×8：(RMSNorm→GQA)→⊕→(RMSNorm→FFN)→⊕   ← 全场最重的 7 页
第四段  出口   ④⑤ RMSNorm + lm_head   →   ⑥ 错一位 loss
第五段  收账   参数 63.9M 花在哪  →  全图检查清单  →  五条可带走的原则
```

**贯穿全场的一个记忆锚**（P3 立、后续每页回踩）：**形状守恒**。
整张图里张量一路都是 `[2, 340, 768]`，只有两个点会膨胀。记住这一句，架构图就记住了一半。

### 第二章 入口：文本怎么变成数（P4~P6）

**P4 ① Tokenizer：文本 → token id**
- 〔任务〕讲清"模型只认识整数"以及补齐的代价
- 要点：① 四步——原始文本 → 分词（`我|爱|蔚蓝|的|天空`）→ 加框（`[bos] … [eos]`）→ 补齐到 340；② **bos/eos** 是句子边界唯一的显式信号，**pad** 是为了把不等长的句子拼成矩形张量做并行；③ 本项目做过**数字逐位切分** patch（`Sequence[Digits, ByteLevel]`），任何数字 0-9 都是独立 token——这是后续数学能力的基础
- 〔素材〕`lm_dataset.py` `PretrainDataset.__getitem__`、`docs/tokenizer_digits.md`；〔视觉〕四行对齐的终端块，pad 段灰化
- 〔关键句〕**"pad 不是"没用的填充"——它是让 batch 能并行的那笔账。"**

**P5 ② Input Embedding：id → 向量**
- 〔任务〕讲清"查表"和"权重共享"，为 P14 的出口埋钩子
- 要点：① 嵌入矩阵 = 一本 **6400 行的字典**，每行一个 token 的 768 维初始语义；`nn.Embedding(6400, 768)`，`[2,340] → [2,340,768]`；② **这个向量是可学习的**——预训练的大部分学习就发生在调整这张表和后面的权重上
- 〔素材〕`model_minimind.py:206 / :219`；〔视觉〕6400×768 网格，"取第 N 行"箭头动画
- 〔关键句〕**"而这张表，和最后的输出层是同一张——省了 4.9M 参数。先记住，P14 我们来兑现。"**

**P6 RoPE 表：位置信息从哪来（预计算，无参数）**
- 〔任务〕把"位置"这件事在本 deck 内闭环，避免听众带着"位置编码呢？"的疑问走到注意力页
- 要点：① 没有位置编码会怎样——"蔚蓝"在第 3 位还是第 30 位，它与"天空"的打分完全一样；② 按 `head_dim=96` 生成 **48 个频率** `f(i) = 1e6^(−2i/96)`，与位置 0~32767 做外积，拼成 `[32768, 96]` 的 cos/sin 两张表；③ 每个 batch 只取前 340 行 → `cos, sin 各 [340, 96]`；④ **是缓冲区，不是参数**——只预计算一次，训练不更新
- 〔素材〕`model_minimind.py:62-78`（预计算）、`:224`（取本批位置）；〔视觉〕两栏：左 `[32768,96]` 全表，右切出 `[340,96]`
- 〔关键句〕**"RoPE 不作用于嵌入向量——它稍后只在注意力内部旋转 Q 和 K。下一章兑现。"**

### 第三章 核心：8 层 × (GQA + FFN)（P7~P13）

**P7 Layer k 骨架：两条残差捷径，两个 Pre-Norm**
- 〔任务〕先给骨架，再拆器官——这一页是"中栏"的骨架
- 要点：① 一层 = `x + GQA(RMSNorm(x))` → `x + FFN(RMSNorm(x))`，两次 `+=` 就是图上那两条**虚线**；② 残差的意义——即使某子层学得不好（输出 ≈ 0），信息也能**无损通过**，几十层才训得动；③ RMSNorm 放在子层**之前**（Pre-Norm），不是之后，这是 LLaMA/Qwen 等现代 LLM 的标准做法，训练更稳定；④ 8 层结构完全相同，但**权重各自独立**，逐层从"字面语义"提炼到"上下文语义"
- 〔素材〕`MiniMindBlock`（`model_minimind.py:183-199`）；〔视觉〕竖直骨架图，两条虚线捷径必须画出来，两个 ⊕ 用圆点强调
- 〔关键句〕**"虚线不是装饰——它是让 8 层能叠起来的那个设计。"**

**P8 GQA 九步：全程唯一会膨胀的张量**
- 〔任务〕一页给完注意力的形状流转全景，让听众先有地图再进细节
- 要点：九步逐行 —— ① QKV 投影 ② 切头 ③ QK-Norm ④ RoPE（只转 Q/K）⑤ 打分 `Q·Kᵀ/√96` ⑥ 因果掩码 ⑦ SoftMax 加权 V ⑧ repeat_kv（GQA 复制）⑨ 合头 + o_proj。每步标形状与行号。**打分阵 `[2,8,340,340]` 是全程唯一会膨胀的中间张量**
- 〔素材〕文档 §6 全链 + 各步行号；〔视觉〕九宫格小卡，卡内：步骤名 / 形状 / 行号，形状等宽着色
- 〔关键句〕**"注意力的全部代价都写在这一个形状里：`[2,8,340,340]`——序列长度的平方。"**

**P9 GQA 逐框（上）：Q / K / V 三路投影与"为什么能省一半"**
- 〔任务〕讲清 QKV 三路投影与 GQA 的收益
- 要点：① 检索类比——**Q**"我想找什么"、**K**"我有什么可以被找到"、**V**"被关注后我实际给出的内容"；② 三路投影：`q_proj 768→768`、`k_proj 768→384`、`v_proj 768→384`，分头后 Q `[2,340,8,96]`、K/V `[2,340,4,96]`；③ **Q 头 8 个、KV 头只有 4 个 = GQA**：4 组 KV 被 8 个 Q 头共享（`n_rep = 2`），KV 参数与 KV cache 直接减半，几乎不损质量；④ N 圈：QK-Norm 对每头 96 维做 RMSNorm，让 softmax 不被个别大值主导
- 〔素材〕`model_minimind.py:100-103 / :117`；〔视觉〕三列 Q/K/V 卡片（配色区分）+ GQA 共享关系的连线图（8 Q 头 ↔ 4 KV 组）
- 〔关键句〕**"8 个 Q 头，只要 4 份 K/V——省下的一半不是近似，是精确的共享。"**

**P10 GQA 逐框（下）：RoPE 只转一半，掩码不许看右边**
- 〔任务〕收掉注意力里三个"为什么"
- 要点：① **RoPE 只旋转 Q 和 K，V 不旋转**——位置信息只需参与"打分"（Q·K），不需参与"内容传递"（V）；② repeat_kv 把 4 份 KV 复制给 8 个 Q 头，再转置成头优先 `[2,8,340,96]`；③ 打分 `[2,8,340,96] @ [2,8,96,340] / √96` → `[2,8,340,340]`，**÷√96** 是防 softmax 饱和（梯度消失）；④ 因果掩码把上三角加 −inf——**预训练是"预测下一个词"，能看到右边就是抄答案**；⑤ softmax @ V 加权求和，含义是"天空"的输出 = 所有位置内容按权重混合
- 〔素材〕`model_minimind.py:80-84 / :119 / :86-89 / :124 / :128-131`；〔视觉〕形状流转条形图，Q/K 路径标"旋转"，V 路径标"不旋转"（用颜色区分）
- 〔关键句〕**"V 不旋转，是因为位置只影响"我要看谁"，不影响"我拿走什么"。"**

**P11 因果掩码可视化 + pad 为什么不用额外屏蔽**
- 〔任务〕用一张图钉死"不许看未来"，并顺手清掉一个常见疑问
- 要点：① 5×5 三角矩阵（我 / 爱 / 蔚蓝 / 的 / 天空），✓ = 分数保留、✗ = −inf → 概率 0；② **pad 需不需要额外屏蔽？不需要**——右 padding 让 pad 全排在真实 token 之后，因果掩码本来就让真实 token 看不到它们；pad 自己虽能看到前面，但 pad 位置的 loss 已标 `-100`
- 〔素材〕文档 §6.7 与补充说明；〔视觉〕真彩 5×5 三角（✓ 实心青 / ✗ 虚线红）
- 〔关键句〕**"右 padding + 因果掩码 + labels=-100，三件事合起来，pad 就自动隐形了。"**

**P12 FFN：SwiGLU 的门控开关**
- 〔任务〕讲清 FFN 的机制与它和注意力的分工
- 要点：① 结构 `Linear → SiLU ⊙ Linear → Linear`，即 `down_proj(SiLU(gate_proj(x)) × up_proj(x))`；② 分工——注意力是**跨位置**通信（让"天空"看到"我爱蔚蓝的"），FFN 是**单位置**加工（每个位置独立做一次 768→2432→768 非线性），承担主要"知识存储"；③ 中间维度 2432 的来历：`ceil(768 × π/64) × 64`——不是随便选的；④ 图中有 Dropout 框，代码里没有（`dropout=0.0` 且 FFN 未实现）——**图上与代码的差异要主动交代**
- 〔素材〕`model_minimind.py:136-146 / :198 / :26`；〔视觉〕横向数据流（x → gate/up 双支 → SiLU → ⊙ → down → x′）
- 〔关键句〕**"SiLU 只作用在 gate 上——谁接了 SiLU，谁就是那个开关。"**

**P13 参数量核算：63.9M 花在哪**
- 〔任务〕给出"账本"，让全场三个数字落袋
- 要点：① QKV+O ≈ 1.77M/层 → **14.2M**；② FFN（SwiGLU）≈ 5.60M/层 → **44.8M**（**约占 70%，参数大头在这里**）；③ 嵌入表（与 lm_head 共享）**4.92M**，只算一份；④ 合计 **≈ 63.9M** ✅；⑤ 两笔"省"：权重共享省 ~4.9M，GQA 让 KV 参数与 cache 减半
- 〔素材〕文档 §10、`:246/:247`；〔视觉〕横向堆叠条 + 两处"省"的抵消箭头
- 〔关键句〕**"这个模型 70% 的参数在 FFN 里——注意力负责搬运信息，FFN 负责存放知识。"**

### 第四章 出口：从 768 维到 loss 标量（P14~P15）

**P14 ④⑤⑥ 出口：RMSNorm → lm_head → logits**
- 〔任务〕讲完出口，兑现 P5 埋下的权重共享伏笔
- 要点：① `self.norm(hidden_states)` → `[2,340,768]`；② `lm_head` = `nn.Linear(768, 6400, bias=False)` → logits `[2,340,6400]`，每个位置对全词表的原始打分；③ **与输入嵌入共享同一份 `[6400,768]` 权重**——正着用是查表的 embedding，反着用就是打分的 lm_head；④ 图顶部的 `SoftMax → Decoder → "hello + world"` 是**推理视角**，预训练走到 loss 就结束了
- 〔素材〕`model_minimind.py:235`（norm 调用）/ `:246`（lm_head 定义）/ `:247`（权重共享）/ `:253`（lm_head 调用）；〔视觉〕同一块矩阵的两个箭头（左标"查表"，右标"打分"）——**一页说明白 P5 的伏笔**
- 〔关键句〕**"同一本字典，正着查是输入，反着用是输出。"**

**P15 错一位：预训练唯一的监督信号**
- 〔任务〕讲清 loss 的含义与训练循环
- 要点：① `x = logits[..., :-1, :]`（`[2,339,6400]`）、`y = labels[..., 1:]`（`[2,339]`）——**位置 i 的打分预测位置 i+1 的 token**；② cross_entropy 四步：softmax → 用答案 id 索引取出正确 token 的概率 → 取 −log → 平均（`ignore_index=-100` 跳过 pad）；③ 本 batch 到底算了多少个：句子 B 7 个真实 token 剩 6 个、句子 A 13 个剩 12 个，**共 18 个有效预测**；④ 之后：梯度累积 → `backward()` → 梯度裁剪 → AdamW 更新，重复成千上万次 step
