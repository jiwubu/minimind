# 数学专用模型训练方案 v1

> 背景：tokenizer 已做数字逐位切分（见 [tokenizer_digits.md](./tokenizer_digits.md)）。
> 上一版方案以空格分隔数字实现加减专项，8 位数实测 99.5%，其格式与采样配比由本方案接替；
> 本方案从零预训练，统一覆盖加减乘除四则。

---

## 0. 总体架构

```
表示层             patched tokenizer：Sequence[Digits, ByteLevel]
                  数字全局一位一 token，id 兼容，6400 词表冻结不重训
                        ↓
预训练（通用）     pretrain_t2t_mini.jsonl，从头训练 64M
                  单数字 embedding 从第一天学习位值语义
                        ↓
数据层             竖式 CoT + 低位优先 + compare_trace + 课程采样
                  插桩实测 + 错例归档的排查方法论，格式适配 patched tokenizer
                        ↓
SFT              预训练权重 + math 数据（30% 通用混合防遗忘）
                        ↓
评测             eval_math.py 分档评测 + eval_llm.py 通用回归
```

分工原则：**「怎么教」（CoT 格式 + 课程数据）是上一版 99.5% 的主要来源；
tokenizer 逐位切分把「怎么切」这个变量从设计空间里消掉**。两者作用于不同层，叠加使用。

从零训练带来一项上一版没有的自由：上一版因「要改格式需重训」而搁置的两个结构性修复
（交换状态行、位数锚点）现在成本为零——没有旧格式 checkpoint 需要兼容，直接纳入本方案。

## 2. 阶段 1：预训练

### 2.1 前置：测量 token 膨胀率

patched tokenizer 对数字密集文本 +32~43%，对自然语料的实际膨胀率必须实测：

```bash
python3 - <<'PY'
import json, random, tempfile, shutil, os
from transformers import AutoTokenizer
new = AutoTokenizer.from_pretrained('model')
# 构造未 patch 对照
tmp = tempfile.mkdtemp(); dst = os.path.join(tmp, 'model'); shutil.copytree('model', dst)
p = os.path.join(dst, 'tokenizer.json'); d = json.load(open(p))
for sub in d['pre_tokenizer']['pretokenizers']:
    if sub['type'] == 'ByteLevel': d['pre_tokenizer'] = sub
json.dump(d, open(p, 'w'), ensure_ascii=False, indent=2)
old = AutoTokenizer.from_pretrained(dst)
lo, to, tn = 0, 0, 0
with open('dataset/pretrain_t2t_mini.jsonl') as f:
    for line in random.Random(0).sample(f.readlines(), 2000):
        t = json.loads(line).get('text', '')
        if not t.strip(): continue
        to += len(old.encode(t)); tn += len(new.encode(t)); lo += len(t)
shutil.rmtree(tmp)
print(f'字符 {lo}  旧 {to} tok  新 {tn} tok  膨胀 {(tn-to)/to:+.1%}')
PY
```

- 膨胀 < 15%：`max_seq_len` 维持 340
- 膨胀 ≥ 15%：提到 384（否则等价语料量缩水）

`python math/stats_math_data.py dataset/<文件>.jsonl`。

**加减法实测**（40 万数学行）：

| 检查项 | 达标线 | 上一版基线 | 实测 |
|---|---|---|---|
| 负数·等长且接近 | ≥ 2% | 0.23% | **2.37%** ✅ |
| 前导零 k=3~7 各档 | ≥ 1% | — | 1.28~2.48% 全过 ✅ |
| 前导零 k≥3 合计 | — | 2.26% | **8.31%**（3.7×） |
| 前导零 k≥5 合计 | — | 0.83% | **4.08%**（4.9×） |
| 答案零串 ≥4 | ≥ 6% | 6.35% | **6.2%** ✅ |
| 轨迹 fuzz（全分支 × 四则 roundtrip + 不变量） | 零失败 | — | **50,880 例零失败**（含乘除 ≈1.1 万）✅ |

交换状态行、位数锚点与语境题，不是 tokenizer（紧凑数字与上一版空格格式 token 数
持平）。**加减单训用 576**（实测 max=557 + 余量）；四则合并训的预算由乘除
主导，**SFT 用 1344**（§7.2），此处的 576 仅在只训加减时适用。

## 6. 轨迹格式（math_format.py）

**加减法改动清单**（相对上一版格式）：

| # | 改动 | 类型 |
|---|---|---|
| F1 | 数字一律紧凑十进制：`竖式计算 431+254` | 格式 |
| F2 | compare_trace 之后加**显式交换状态行**，交换与否都声明：`15 < 17，交换后计算 17 - 15` | 格式 |
| F3 | 答案行加位数锚点：`答案(3位): 685` | 格式 |
| D1 | `sample_negative_pair` 等长档改为共享高位前缀、末几位分出大小 | 采样 |
| D2 | 新增 `sample_leadzero_pair`：结果需去掉 k 个前导零，k∈[1, n-1] 均匀 | 采样 |

输出示例（负数场景，F2 + F3 可见，为 `build_trace(15,'-',17)` 真实输出）：

```
先比较 15 和 17 的大小
位数相同，都是 2 位，从最高位逐位比较
十位: 1 = 1，相同，继续比下一位
个位: 5 < 7，分出大小，所以 17 更大
15 < 17，交换后计算 17 - 15
竖式计算 17 - 15
个位: 7 - 5 - 0 = 2，写 2 借位 0
十位: 1 - 1 - 0 = 0，写 0 借位 0
去掉前导零
逆序: 2
答案(1位): 2
结果为负: -2
```

**新增模板类：自然语境数字题**：混入「这双鞋 1250 元」「2023 年有 365 天」类
问答，训练自然文本里的数字读题。占比约 5%，题面来自模板 + 随机数字。

**保留不动**：低位优先演算、compare_trace 逐位比较、口语模板、
15% system prompt、操作数随机交换、`mix_ratio 0.3`、生成与解析共用
math_format.py 的单点维护原则。

**乘除法**（与加减法同规：`math_format.py` 单点维护、生成与解析共用、
fuzz 过门才能改格式、数字一律紧凑十进制）：

**乘法 `mul_trace` = 部分积竖式**：

- 乘数取位数少的操作数，首行显式声明（`乘数用位数少的 254，逐位乘 431`）
  —— 与减法交换状态行同理，选择是可寻址 token 而非隐式状态；
- 乘数每一位单独成行，逐位乘行与加法进位行同构：`十位: 3 * 4 + 1 = 13，写 3 进位 1`；
- 错位不靠心算对齐，补零后的完整数显式写出：`第2行结果: 2155，错 1 位: 21550`；
- 逐行两两累加，复用 `_add_core`；中间累加行尾写 `合计:` 而非 `答案:`
  —— **一条轨迹只允许一个答案行**，否则 `parse_answer` 命中的是中间结果。

**除法 `div_trace` = 长除法 + 显式试商**（784 / 16 真实输出节选）：

```
十位: 78 试商
16 * 4
个位: 6 * 4 = 24，写 4 进位 2
十位: 1 * 4 + 2 = 6，写 6 进位 0
16 * 4 = 64
64 <= 78，够减，逐位减
个位: 8 - 4 - 0 = 4，写 4 借位 0
十位: 7 - 6 - 0 = 1，写 1 借位 0
差: 14
14 < 16，商 4
落下 4，14 * 10 + 4 = 144
```

- 真商 `rem // b` 是除法**唯一的高熵决策**（原判断成立）。对策：候选积逐位
  展开验证（一位除数是口诀一行；多位除数展开成乘法行同构块），偏大则
  `太大，试 c-1` 逐个下调；数据侧 30% 样本让首个候选故意偏大 1~2
  （overshoot），教模型走自纠路径 —— 推理时猜偏也能收敛；
- 每商位：试商 → 验证 → 逐位减（复用 `_sub_core`）→ `落下 d，r * 10 + d = …`；
- 末行 `余数: X` 与减法 `结果为负:` 同构，`parse_remainder` 单独解析；
  被除数 < 除数是独立分支（`商 0 余 a`）。

**符号与问法**：tokenizer 下 `*` `/` 是单 token；`×` `÷` 是多字节碎片，题面
一律 ASCII。口语只保留无歧义的「乘/乘以/除以」（裸「除」语义反向，禁用）。

**原理与依据**（每条改动为什么这么改；乘除各 bullet 的设计依据已内联在上文）：

- **F1（`spaced()` 退役）**：patched 下 `685` 天然就是 `['6','8','5']`，与旧
  格式 `'6 8 5'` 的 `['6','Ġ8','Ġ5']` token 数持平（实测 3 tok ↔ 3 tok），
  但不再依赖词表里 `Ġ+数字` merge 的存在性——该 merge 在 patched 下已死。
  空格分隔是"不能动 tokenizer"时代的 workaround，表示层对齐交给 tokenizer
  后随之退役，格式里数字一律紧凑十进制。
- **F2**：上一版负数错例集中在模型跳过交换、直接对 小-大 跑借位，得到 10 的
  补码（`15-17 → 98`）。交换与否都写成显式行，让「是否已交换」成为可寻址
  token 而非隐式状态。
- **F3**：上一版实测反转拷贝的终止判断是高熵区——"已写 k 个 0 要不要继续"在
  k=4 时 P(继续)=53.7%，几乎掷硬币。先声明总位数，写答案变成「抄够 N 位就停」。
- **D1**：上一版负数档的全部错例都是等长且接近的形状；旧采样均匀取 a，该形状
  覆盖仅 0.23%。共享前缀构造把它抬到 ≥2%。
- **D2**：上一版只有两个极端——k=1~2 靠自然命中、k=n 全塌缩靠 equal 档构造，
  中间深度 k=3~6 无任何分支，实测去 5 个前导零时把 `111` 一起吃掉。
- **语境题**：旧格式下自然文本里的数字（2023、1250）被 BPE 合成与数位无关
  的块，模型读题位值是乱的；patched 的全局位值对齐让这类题第一次可训，
  是上一版做不到的能力。

## 7. 阶段 5：乘除法（数据已就绪 ✅，训练/评测待服务器）

> 轨迹格式在 §6（与加减法同节单点维护，`math_format.py`）。本节覆盖
> 乘除的数据生成、序列长度预算、合并训练方案、评测与风险。

### 7.1 数据生成与插桩实测

`math/gen_math_data_muldiv.py`：默认 `--max_digits 4`（乘 4×4、除 4位÷2位，
小学常见范围）。乘法 8 档（通用/一位乘数/末尾零/内嵌0/整十幂/全同数字/9串/相等），
除法 4 档（通用/商含0/零串/商0）+ overshoot 修正档 + 自然语境题（除法语境只出
整除样本）。难度档构造逻辑与加减法同源：随机采样采不到的形状必须显式构造。

**实测**（40 万乘除行，`math/stats_math_data.py`）：

| 检查项 | 达标线 | 实测 |
|---|---|---|
| 乘 : 除 | 50/50 | 49.9 / 50.1 ✅ |
| 自然语境 | ~5% | 5.0% ✅ |
| 试商修正（轨迹含 `太大`） | 理论 27% | 27.4% ✅ |
| 带余数 | 组合模型 35.8% | 35.8% ✅ |
| 商含 0 / 除数 1 位 | — | 30.0% / 50.2% |
| fuzz roundtrip | 零失败 | 50,880 例零失败（含乘除 ≈1.1 万）✅ |

### 7.2 序列长度预算 → SFT `max_seq_len = 1344`

| 档位 | token max |
|---|---|
| 乘 3×3 | 744 |
| 乘 4×4 | 1263 |
| 除 4位÷1位 | 543 |
| 除 4位÷2位（overshoot 0 / 2） | 725 / 1232 |

全量 40 万行边界带（字符 >1250，共 10,480 条）逐一实测 token：**0 条超过
1344**——字符最长的 9999*9999（1350 字符）≈ 1300 token，演算行高频短语被
BPE 合并。**SFT 用 1344，最难例零截断**（§3 同一原则）；预算紧张可
`--max_digits 3` 降回 896。

### 7.3 训练方案：合并训，文件分开维护

目标是**单个模型会四则**。两个独立模型直接排除；「先加减、再续训乘除」也不取
—— 要防遗忘就得把加减数据混回去，混回去之后就是合并训练，白绕一步（且 §4
反对在旧 math 权重上增量）。乘除轨迹内嵌加减原语（部分积累加=加法、除法减步
=减法，行格式同构），一起训共享竖式表示，是正迁移而非互相干扰。

`dataset/math_all_v1.jsonl` = math_addsub_v1 + math_muldiv_v1 直接拼接
（1,142,856 条；不做文件级洗牌，理由与代价见 §3）。数学行四运算
22.3 / 27.7 / 24.9 / 25.1%，通用回放 30.0%（两份文件各自 70/30，拼接后
比例不变，无需重新配平）。

```bash
cd trainer && python train_full_sft.py \
  --data_path ../dataset/math_all_v1.jsonl \
  --from_weight pretrain_math \
  --save_weight full_sft_math_all_v1 \
  --epochs 1 --batch_size 32 --learning_rate 2e-5 \
  --max_seq_len 1344 \
  --dtype bfloat16 --num_workers 8 --from_resume 1
```

代价说明：`SFTDataset` 定长 padding（lm_dataset.py:115），全量按 1344 pad
≈ 1.53B token-slots/epoch，比按运算符分开训（≈1.10B）多 ~40%；对 64M 是
小时级开销，接受。优化点在 trainer 侧按长度分桶，暂不做。

### 7.4 评测（✅ 已补齐）

`eval_math.py` 已加乘除分档，与训练课程一一对应：乘法八档直接复用训练采样器
（评测形状 = 训练形状）；除法拆整除/带余（`parse_remainder` 对商、余数双判分）
+ 商含0/商零串/小除以大，除法专项统计除数位数 × 首候选是否命中（轨迹含`太大`）
—— 验证 overshoot 自纠路径是否真的救回猜偏的样本，这是 7.5 第一条风险的
直接观测点。`--max_new_tokens` 默认提到 1500（乘除轨迹最长 ≈1300，加减仅 ≈440）。

### 7.5 风险

| 风险 | 对策 |
|---|---|
| 真商猜测的自纠失效（overshoot 只覆盖偏大 1~2，模型实际猜偏可能更深） | 服务器实测除法分档准确率（7.4）；若 2 位除数塌陷，先砍到 1 位除数保乘法收益 |
| 乘法错位累加抄错（长零串 / 全同数字叠加） | 难例档已显式构造；沿用错例档案方法定位 |
| 定长 padding 拉长训练 | 接受（7.3）；或 trainer 长度分桶，暂不做 |

## 8. 风险与对策

| 风险 | 对策 |
