# 数学专用模型训练方案

> 背景：tokenizer 已做数字逐位切分（见 [tokenizer_digits.md](./tokenizer_digits.md)）。
> 本方案从零预训练，统一覆盖加减乘除四则。

---

## 0. 总体架构

```
表示层             patched tokenizer：Sequence[Digits, ByteLevel]
                  数字全局一位一 token，id 兼容，6400 词表冻结不重训
                        ↓
预训练（通用）     pretrain_t2t_mini.jsonl，从头训练 64M
                  单数字 embedding 从第一天学习位值语义
                        ↓
数据层             竖式 CoT + 低位优先 + compare_trace + 课程采样
                  插桩实测 + 错例归档的排查方法论，格式适配 patched tokenizer
                        ↓
SFT              预训练权重 + math 数据（30% 通用混合防遗忘）
                        ↓
评测             eval_math.py 分档评测 + eval_llm.py 通用回归
```

分工原则：**「怎么教」（CoT 格式 + 课程数据）负责注入算术能力；
tokenizer 逐位切分把「怎么切」这个变量从设计空间里消掉**。两者作用于不同层，叠加使用。

从零训练带来一项自由：交换状态行、位数锚点两个结构性修复成本为零——
没有旧格式 checkpoint 需要兼容，直接纳入本方案。

## 2. 阶段 1：预训练

### 2.1 前置：测量 token 膨胀率

patched tokenizer 对数字密集文本 +32~43%，对自然语料的实际膨胀率必须实测：

```bash
python3 - <<'PY'
import json, random, tempfile, shutil, os
from transformers import AutoTokenizer
new = AutoTokenizer.from_pretrained('model')
# 构造未 patch 对照
tmp = tempfile.mkdtemp(); dst = os.path.join(tmp, 'model'); shutil.copytree('model', dst)
p = os.path.join(dst, 'tokenizer.json'); d = json.load(open(p))
for sub in d['pre_tokenizer']['pretokenizers']:
    if sub['type'] == 'ByteLevel': d['pre_tokenizer'] = sub
json.dump(d, open(p, 'w'), ensure_ascii=False, indent=2)
old = AutoTokenizer.from_pretrained(dst)
lo, to, tn = 0, 0, 0
with open('dataset/pretrain_t2t_mini.jsonl') as f:
    for line in random.Random(0).sample(f.readlines(), 2000):
        t = json.loads(line).get('text', '')
        if not t.strip(): continue
        to += len(old.encode(t)); tn += len(new.encode(t)); lo += len(t)
shutil.rmtree(tmp)
print(f'字符 {lo}  旧 {to} tok  新 {tn} tok  膨胀 {(tn-to)/to:+.1%}')
PY
```

- 膨胀 < 15%：`max_seq_len` 维持 340
- 膨胀 ≥ 15%：提到 384（否则等价语料量缩水）

### 2.2 从零预训练（64M 默认配置）

```bash
cd trainer && python train_pretrain.py \
  --data_path ../dataset/pretrain_t2t_mini.jsonl \
  --from_weight none \
  --save_weight pretrain_math \
  --max_seq_len 340 \
  --epochs 2 --batch_size 32 --dtype bfloat16 --from_resume 1
```

**明确不做**：预训练语料不掺算术。算术能力全部由 SFT 的 CoT 承担——分层设计有效；
预训练阶段 patched tokenizer 的职责只是让数字以位值对齐的形态进入模型。

## 3. 阶段 2：数据生成与插桩自检（设了 X% 必须实测命中 X%）

加减与乘除两个生成器各自产出、各自插桩，最后拼接为训练文件：

```bash
# 1) 加减法：40 万数学行 + 30% 通用回放
python math/gen_math_data_addsub.py \
  --out dataset/sft_math_addsub_v3.jsonl \
  --n 400000 --max_digits 8 \
  --mix_general dataset/sft_t2t_mini.jsonl --mix_ratio 0.3

# 2) 乘除法（§7.1）：40 万数学行 + 30% 通用回放；乘 4×4、除 4位÷2位
python math/gen_math_data_muldiv.py \
  --out dataset/sft_math_muldiv_v3.jsonl \
  --n 400000 \
  --mix_general dataset/sft_t2t_mini.jsonl --mix_ratio 0.3

# 3) 拼接 → 合并训练文件（§7.2；两文件各自 70/30，拼接后比例不变）
#    不做文件级洗牌：生成器写盘前已各自打散（数学/通用交错），训练侧每 epoch
#    还会重新洗牌（单卡 randperm / DDP DistributedSampler），"前半加减、后半
#    乘除"的块结构对训练无影响。代价：将来若要切验证集，别按行顺序切
#    （会切出纯乘除），用随机抽样切。
cat dataset/sft_math_addsub_v3.jsonl dataset/sft_math_muldiv_v3.jsonl > dataset/sft_math_all_v3.jsonl
wc -l dataset/sft_math_all_v3.jsonl    # 应为 1,142,856
```

生成后必须插桩实测（设了 X% 不等于命中 X%）：
`python math/stats_math_data.py dataset/<文件>.jsonl`。
乘除专档（试商修正 / 带余数 / 商含 0 / 除数位数）的实测表见 §7.1。

**加减法实测**（40 万数学行）：

| 检查项 | 达标线 | 实测 |
|---|---|---|
| 负数·等长且接近 | ≥ 2% | **2.37%** ✅ |
| 前导零 k=3~7 各档 | ≥ 1% | 1.28~2.48% 全过 ✅ |
| 前导零 k≥3 合计 | — | **8.31%** |
| 前导零 k≥5 合计 | — | **4.08%** |
| 答案零串 ≥4 | ≥ 6% | **6.2%** ✅ |
| 轨迹 fuzz（全分支 × 四则 roundtrip + 不变量） | 零失败 | **50,880 例零失败**（含乘除 ≈1.1 万）✅ |
| 序列长度 median / p95 / max（加减） | 重测定 `max_seq_len` | 251 / 459 / 557 |

序列长度结论（加减部分）：`max_seq_len=512` 会截掉 0.66% 的样本——恰好是
8 位数的最长（最难）样本，系统性截断最难例不可接受。变长的来源是新增的
交换状态行、位数锚点与语境题，不是 tokenizer。**加减单训用 576**（实测 max=557 + 余量）；四则合并训的预算由乘除
主导，**SFT 用 1344**（§7.2），此处的 576 仅在只训加减时适用。

## 5. 阶段 4：评测与验收

```bash
python math/eval_math.py --weight full_sft_math_v3 --max_digits 8 --n 25   # 分档评测
python eval_llm.py --weight full_sft_math_v3                       # 通用回归
```

评测器与 math_format.py 单点维护，格式改动自动跟随。新增桶：
`neg_close`（等长且接近负数）、`leadzero_k`（按 k 分桶）——**改了数据必须同步改评测**，
否则看不见收益（档位总分达标而档内分布塌陷，是最容易复发的评测盲区）。

验收指标：

| 指标 | 目标 | 实测 |
|---|---|---|
| 加减 8 位总体准确率 | ≥ 99.5% | 8 位各档 96~100% ✅ |
| 负数·等长且接近 | ≥ 98% | 95.4% ⚠️ 按预登记规则（≥95）接受，详见 v3 档案 |

| 错例归档 | 逐档全量归档 | ✅ [v3 结果与错例档案](./数学专用模型v3结果与错例档案.md) |

## 6. 轨迹格式（math_format.py）

**加减法格式**：

- 数字一律紧凑十进制：`竖式计算 431+254`（patched 下 `685` 天然就是 `['6','8','5']`）
- **显式交换状态行**：`15 < 17，交换后计算 17 - 15`——防止模型跳过交换、直接对 小-大 跑借位得到 10 的补码（`15-17 → 98`），让「是否已交换」成为可寻址 token 而非隐式状态
- **答案行位数锚点**：`答案(3位): 685`——反转拷贝的终止判断是高熵区（k=4 时 P(继续)=53.7%，几乎掷硬币），先声明总位数，写答案变成「抄够 N 位就停」
- **倒计时状态锚**：`十位: 5 = 5，相同，还剩 2 位`——长相同链上位置跟踪衰减的对策，neg_close 实测 95.4
- **采样构造**：等长且接近的负数形状均匀采样仅覆盖 0.23%，`sample_negative_pair` 用共享高位前缀抬到 ≥2%；`sample_leadzero_pair` 显式构造中间深度（k=3~6）前导零分支
- **自然语境数字题**：混入「这双鞋 1250 元」「2023 年有 365 天」类问答，占比约 5%——patched 的全局位值对齐让自然文本数字读题可训

输出示例（`build_trace(15,'-',17)` 真实输出）：

```
先比较 15 和 17 的大小
位数相同，都是 2 位，从最高位逐位比较
十位: 1 = 1，相同，继续比下一位
个位: 5 < 7，分出大小，所以 17 更大
15 < 17，交换后计算 17 - 15
竖式计算 17 - 15
个位: 7 - 5 - 0 = 2，写 2 借位 0
十位: 1 - 1 - 0 = 0，写 0 借位 0
去掉前导零
逆序: 2
答案(1位): 2
结果为负: -2
```

**保留不动**：低位优先演算、compare_trace 逐位比较、口语模板、15% system prompt、操作数随机交换、`mix_ratio 0.3`、生成与解析共用 math_format.py 的单点维护原则。

**乘除法**（与加减法同规：单点维护、生成与解析共用、fuzz 过门才能改格式、数字一律紧凑十进制）：

- **乘法 = 部分积竖式**：乘数取位数少的操作数并在首行显式声明（与交换状态行同理，选择是可寻址 token 而非隐式状态）；每一位单独成行（`十位: 3 * 4 + 1 = 13，写 3 进位 1`）；错位补零后的完整数显式写出（`第2行结果: 2155，错 1 位: 21550`）；逐行两两累加复用 `_add_core`，中间行尾写 `合计:`——**一条轨迹只允许一个答案行**，否则 `parse_answer` 命中的是中间结果
- **除法 = 长除法 + 显式试商**：真商 `rem // b` 是除法**唯一的高熵决策**，候选积逐位展开验证（多位除数展开成乘法行同构块），偏大则 `太大，试 c-1` 逐个下调；数据侧 30% 样本让首个候选故意偏大 1~2（overshoot），教模型走自纠路径——推理时猜偏也能收敛；每商位：试商 → 验证 → 逐位减（复用 `_sub_core`）→ 落下；末行 `余数: X` 由 `parse_remainder` 单独解析，被除数 < 除数走 `商 0 余 a` 独立分支
- **符号与问法**：题面一律 ASCII（`*` `/` 是单 token，`×` `÷` 是多字节碎片）；口语只保留无歧义的「乘/乘以/除以」（裸「除」语义反向，禁用）

## 7. 阶段 5：乘除法（✅ 已完成）

### 7.1 数据生成与插桩实测

`math/gen_math_data_muldiv.py`：默认 `--max_digits 4`（乘 4×4、除 4位÷2位，
小学常见范围）。乘法 8 档 + 除法 4 档 + overshoot 修正档 + 自然语境题（只出
整除）。随机采样采不到的形状必须显式构造。

实测（40 万乘除行，`math/stats_math_data.py`）：乘 : 除 = 49.9 / 50.1、
自然语境 5.0%、试商修正 27.4%、带余数 35.8%、fuzz 50,880 例零失败（含乘除
≈1.1 万）✅。

### 7.2 序列长度与合并训练

字符最长的 9999*9999（1350 字符）≈ 1300 token，全量边界带实测 **0 条超过
1344**，SFT 用 `max_seq_len=1344` 最难例零截断（§3 同一原则）。

合并训取**单个模型会四则**：乘除轨迹内嵌加减原语（部分积累加=加法、除法减步
=减法，行格式同构），一起训共享竖式表示，是正迁移；不拆独立模型，也不做
「先加减、再续训乘除」——要防遗忘就得把加减数据混回，等于绕回合并训练。

```bash
cd trainer && python train_full_sft.py \
  --data_path ../dataset/math_all_v3.jsonl \
  --from_weight pretrain_math \
  --save_weight full_sft_math_all_v3 \
  --epochs 1 --batch_size 32 --learning_rate 2e-5 \
  --max_seq_len 1344 \
  --dtype bfloat16 --num_workers 8 --from_resume 1
```

`math_all_v3.jsonl` = addsub + muldiv 直接拼接（1,142,856 条），数学行四运算
22.3 / 27.7 / 24.9 / 25.1%，通用回放 30.0%。代价：定长 padding 全量按 1344
pad 比按运算符分开训多 ~40% token-slots，对 64M 是小时级开销，接受。

### 7.3 评测

`eval_math.py` 乘除分档与训练课程一一对应：乘法八档直接复用训练采样器；
除法拆整除/带余（`parse_remainder` 对商、余数双判分）+ 商含0/商零串/小除以大，
专项统计除数位数 × 首候选命中——验证 overshoot 自纠是否救回猜偏样本。
`--max_new_tokens` 默认 1500。快速迭代用 `math/eval_math_fast.py`（约 1/10
耗时），验收与错例归档用全量版。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 真商猜测的自纠失效（overshoot 只覆盖偏大 1~2，模型实际猜偏可能更深） | 除法分档实测（§7.3）；若 2 位除数塌陷，砍到 1 位除数保乘法收益 |
| 乘法错位累加抄错（长零串 / 全同数字叠加） | 难例档已显式构造；沿用错例档案方法定位 |
| token 膨胀挤占上下文 | §2.1 先实测再定 `max_seq_len` |
| 格式改动引入**新**失败模式 | 插桩统计 + 错例反推 + 手工试探 |
| 灾难性遗忘 | `mix_ratio 0.3` 混入通用语料 |
| 定长 padding 拉长训练 | 接受（§7.2）；或 trainer 长度分桶，暂不做 |
| 双模式输出（简短直答 vs 竖式） | 暂不做，列为后续增强（1–2 位直答、3 位以上展开） |
| 评测盲区复发 | 评测集先按符号/位数/接近度/写法反向统计找 0 格，再开训 |
