# 数学专用模型训练方案 v6（tokenizer 补丁 × 竖式 CoT 组合）

> 前置文档：[tokenizer_digits.md](../docs/tokenizer_digits.md)（方案 1：表示层）、
> [加减法能力提升方案.md](./加减法能力提升方案.md)（方案 2：数据层，v5 已达 99.5%）
> 场景变化：**从零预训练**。方案 2 的前提「tokenizer 已冻结、不能重跑预训练」不再成立，
> 两个方案从二选一变成分层叠加。

---

## 0. 总体架构

```
表示层（方案 1）   patched tokenizer：Sequence[Digits, ByteLevel]
                  数字全局一位一 token，id 兼容，6400 词表冻结不重训
                        ↓
预训练（通用）     pretrain_t2t_mini.jsonl，从头训练 64M
                  单数字 embedding 从第一天学习位值语义
                        ↓
数据层（方案 2）   v6 竖式 CoT + 低位优先 + compare_trace + 课程采样
                  继承 12 轮方法论，格式适配 patched tokenizer
                        ↓
SFT              预训练权重 + math 数据（30% 通用混合防遗忘）
                        ↓
评测（方案 2）     eval_math.py 十档评测 + 新桶 + eval_llm.py 通用回归
```

分工原则：**方案 2 已证明「怎么教」（CoT 格式 + 课程数据）是 99.5% 的主要来源；
方案 1 把「怎么切」这个变量从设计空间里消掉**。两者作用于不同层，叠加使用。

从零训练带来一项方案 2 没有的自由：**§7.4 两个「结构性修复（要改格式重训，暂不做）」
现在成本为零**——没有旧格式 checkpoint 需要兼容，直接纳入 v6 格式。

## 2. 阶段 1：预训练

### 2.1 前置：测量 token 膨胀率

patched tokenizer 对数字密集文本 +32~43%，对自然语料的实际膨胀率必须实测（方法论 #6）：

```bash
python3 - <<'PY'
import json, random, tempfile, shutil, os
from transformers import AutoTokenizer
new = AutoTokenizer.from_pretrained('model')
# 构造未 patch 对照
tmp = tempfile.mkdtemp(); dst = os.path.join(tmp, 'model'); shutil.copytree('model', dst)
p = os.path.join(dst, 'tokenizer.json'); d = json.load(open(p))
for sub in d['pre_tokenizer']['pretokenizers']:
    if sub['type'] == 'ByteLevel': d['pre_tokenizer'] = sub
json.dump(d, open(p, 'w'), ensure_ascii=False, indent=2)
old = AutoTokenizer.from_pretrained(dst)
lo, to, tn = 0, 0, 0
with open('dataset/pretrain_t2t_mini.jsonl') as f:
    for line in random.Random(0).sample(f.readlines(), 2000):
        t = json.loads(line).get('text', '')
        if not t.strip(): continue
        to += len(old.encode(t)); tn += len(new.encode(t)); lo += len(t)
shutil.rmtree(tmp)
print(f'字符 {lo}  旧 {to} tok  新 {tn} tok  膨胀 {(tn-to)/to:+.1%}')
PY
```

- 膨胀 < 15%：`max_seq_len` 维持 340
- 膨胀 ≥ 15%：提到 384（否则等价语料量缩水）

## 3. 阶段 2：v6 轨迹格式与数据生成

### 3.1 math_format.py v6（一处原则 + 三处格式改动 + 两处数据修复）

**原则：`spaced()` 退役。** patched 下 `685` 天然就是 `['6','8','5']`，
与旧格式 `'6 8 5'` 的 `['6','Ġ8','Ġ5']` token 数持平，但不再依赖词表里
`Ġ+数字` merge 的存在性（该 merge 在 patched 下已死，实测确认）。
格式里所有数字一律写紧凑十进制。

| # | 改动 | 解决 | 来源 |
|---|---|---|---|
| F1 | 全部去空格：`竖式计算 431+254` | 表示层对齐交给 tokenizer | 本方案（实测 3 tok ↔ 3 tok） |
| F2 | compare_trace 之后加**显式交换状态行**：`15 < 17，交换后计算 17 - 15`（不交换同样显式声明） | §6.1 负数档 96.6% 的残留：让「是否已交换」成为可寻址 token 而非隐式状态 | 方案 2 §7.4 |
| F3 | 答案行加位数锚点：`答案(3位): 685` | §6.5 反转拷贝终止判断高熵（k=4 时 P(继续)=53.7%）：先声明总长，写答案变成「抄够 N 位就停」 | 方案 2 §7.4 |
| D1 | `sample_negative_pair` 等长档内让 a 贴着 b 取（共享高位前缀、末几位分出大小），覆盖 0.23% → ≥2% | §7.1 主修项 | 方案 2 §7.1 |
| D2 | `sample_equal_pair` 扩成「去 k 个前导零」，k∈[1, n-1] 均匀 | §6.2 中间深度前导零空档 | 方案 2 §7.2 |

v6 输出示例（负数场景，F2 + F3 可见，为 `build_trace(15,'-',17)` 真实输出）：

```
先比较 15 和 17 的大小
位数相同，都是 2 位，从最高位逐位比较
十位: 1 = 1，相同，继续比下一位
个位: 5 < 7，分出大小，所以 17 更大
15 < 17，交换后计算 17 - 15
竖式计算 17 - 15
个位: 7 - 5 - 0 = 2，写 2 借位 0
十位: 1 - 1 - 0 = 0，写 0 借位 0
去掉前导零
逆序: 2
答案(1位): 2
结果为负: -2
```

**新增模板类：自然语境数字题**（旧方案做不到的能力）。利用 patched 的全局位值对齐，
混入「这双鞋 1250 元」「2023 年有 365 天」类问答，训练自然文本里的数字读题。
占比约 5%，题面来自模板 + 随机数字。

**保留不动**：低位优先演算、compare_trace 逐位比较、11→9 种算式模板
（带空格 8 种合并后与紧凑模板等价）、口语模板、15% system prompt、
操作数随机交换、`mix_ratio 0.3`、生成与解析共用 math_format.py 的单点维护原则。

### 3.2 生成与插桩自检（方法论 #6 硬性要求）

|---|---|---|---|
| 负数·等长且接近 | ≥ 2% | 0.23% | **2.37%** ✅ |
| 前导零 k=3~7 各档 | ≥ 1% | — | 1.28~2.48% 全过 ✅ |

## 6. 阶段 5：乘除法（v1 格式与数据已就绪 ✅，训练/评测待服务器）

> 按本节原设计落地：乘法走部分积竖式（toy 实验 34%→44.4% 的表示层收益之上，
> 补齐格式层）；除法试商用「显式候选 + 自纠」拆一次性决策。格式单点维护在
> `math_format.py`，与加减法同规：生成与解析共用， fuzz 过门才能改格式。

### 6.1 轨迹格式（math_format.py）

**乘法 `mul_trace` = 部分积竖式**：

- 乘数取位数少的操作数，首行显式声明（`乘数用位数少的 254，逐位乘 431`）
  —— 与减法交换状态行同理，选择是可寻址 token 而非隐式状态；
- 乘数每一位单独成行，逐位乘行与加法进位行同构：`十位: 3 * 4 + 1 = 13，写 3 进位 1`；
- 错位不靠心算对齐，补零后的完整数显式写出：`第2行结果: 2155，错 1 位: 21550`；
- 逐行两两累加，复用 `_add_core`；中间累加行尾写 `合计:` 而非 `答案:`
  —— **一条轨迹只允许一个答案行**，否则 `parse_answer` 命中的是中间结果。

**除法 `div_trace` = 长除法 + 显式试商**（784 / 16 真实输出节选）：

```
十位: 78 试商
16 * 4
个位: 6 * 4 = 24，写 4 进位 2
十位: 1 * 4 + 2 = 6，写 6 进位 0
16 * 4 = 64
64 <= 78，够减，逐位减
个位: 8 - 4 - 0 = 4，写 4 借位 0
十位: 7 - 6 - 0 = 1，写 1 借位 0
差: 14
14 < 16，商 4
落下 4，14 * 10 + 4 = 144
```

- 真商 `rem // b` 是除法**唯一的高熵决策**（原判断成立）。对策：候选积逐位
  展开验证（一位除数是口诀一行；多位除数展开成乘法行同构块），偏大则
  `太大，试 c-1` 逐个下调；数据侧 30% 样本让首个候选故意偏大 1~2
  （overshoot），教模型走自纠路径 —— 推理时猜偏也能收敛；
- 每商位：试商 → 验证 → 逐位减（复用 `_sub_core`）→ `落下 d，r * 10 + d = …`；
- 末行 `余数: X` 与减法 `结果为负:` 同构，`parse_remainder` 单独解析；
  被除数 < 除数是独立分支（`商 0 余 a`）。

**符号与问法**：tokenizer 下 `*` `/` 是单 token；`×` `÷` 是多字节碎片，题面
一律 ASCII。口语只保留无歧义的「乘/乘以/除以」（裸「除」语义反向，禁用）。

### 6.2 数据生成与插桩实测

`math/gen_math_data_muldiv.py`：默认 `--max_digits 4`（乘 4×4、除 4位÷2位，
小学常见范围）。乘法 8 档（通用/一位乘数/末尾零/内嵌0/整十幂/全同数字/9串/相等），
除法 4 档（通用/商含0/零串/商0）+ overshoot 修正档 + 自然语境题（除法语境只出
整除样本）。难度档构造逻辑与加减法同源：随机采样采不到的形状必须显式构造。

**v1 实测**（40 万乘除行，`math/stats_math_data.py`）：

| 检查项 | 达标线 | v1 实测 |
|---|---|---|
| 乘 : 除 | 50/50 | 49.9 / 50.1 ✅ |
| 自然语境 | ~5% | 5.0% ✅ |
| 试商修正（轨迹含 `太大`） | 理论 27% | 27.4% ✅ |
| 带余数 | 组合模型 35.8% | 35.8% ✅ |
| 商含 0 / 除数 1 位 | — | 30.0% / 50.2% |
| fuzz roundtrip | 零失败 | 50,880 例零失败（含乘除 ≈1.1 万）✅ |

### 6.3 序列长度预算 → SFT `max_seq_len = 1344`

| 档位 | token max |
|---|---|
| 乘 3×3 | 744 |
| 乘 4×4 | 1263 |
| 除 4位÷1位 | 543 |
| 除 4位÷2位（overshoot 0 / 2） | 725 / 1232 |

全量 40 万行边界带（字符 >1250，共 10,480 条）逐一实测 token：**0 条超过
1344**——字符最长的 9999*9999（1350 字符）≈ 1300 token，演算行高频短语被
BPE 合并。**SFT 用 1344，最难例零截断**（§3.2 同一原则）；预算紧张可
`--max_digits 3` 降回 896。

### 6.4 训练方案：合并训，文件分开维护

目标是**单个模型会四则**。两个独立模型直接排除；「先加减、再续训乘除」也不取
—— 要防遗忘就得把加减数据混回去，混回去之后就是合并训练，白绕一步（且 §4
反对在旧 math 权重上增量）。乘除轨迹内嵌加减原语（部分积累加=加法、除法减步
=减法，行格式同构），一起训共享竖式表示，是正迁移而非互相干扰。

`dataset/math_all_v7.jsonl` = math_addsub_v6 + math_muldiv_v1 拼接洗牌
（seed 42，1,142,856 条）：数学行四运算 22.3 / 27.7 / 24.9 / 25.1%，通用回放
30.0%（两份文件各自 70/30，拼接后比例不变，无需重新配平）。

```bash
cd trainer && python train_full_sft.py \
  --data_path ../dataset/math_all_v7.jsonl \
  --from_weight pretrain_math \
  --save_weight full_sft_math_all_v7 \
  --epochs 1 --batch_size 32 --learning_rate 2e-5 \
  --max_seq_len 1344 \
  --dtype bfloat16 --num_workers 8 --from_resume 1
```

代价说明：`SFTDataset` 定长 padding（lm_dataset.py:115），全量按 1344 pad
≈ 1.53B token-slots/epoch，比按运算符分开训（≈1.10B）多 ~40%；对 64M 是
小时级开销，接受。优化点在 trainer 侧按长度分桶，暂不做。

### 6.5 评测（训练前必须补齐）

`eval_math.py` 尚无乘除分档。按「改了数据必须同步改评测」的规矩，训练前加桶：
乘除 × 位数 ×（整除/带余）×（商含0/商无0），带余题用 `parse_remainder` 对商、
余数双判分；除法按「首候选是否命中」单独统计 —— 验证 overshoot 自纠路径
是否真的救回猜偏的样本，这是 6.6 第一条风险的直接观测点。

### 6.6 风险

| 风险 | 对策 |
|---|---|
| 真商猜测的自纠失效（overshoot 只覆盖偏大 1~2，模型实际猜偏可能更深） | 服务器实测除法分档准确率（6.5）；若 2 位除数塌陷，先砍到 1 位除数保乘法收益 |
| 乘法错位累加抄错（长零串 / 全同数字叠加） | 难例档已显式构造；沿用错例档案方法定位 |
| 定长 padding 拉长训练 | 接受（6.4）；或 trainer 长度分桶，暂不做 |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| token 膨胀挤占上下文 | §2.1 先实测再定 `max_seq_len`；v6 去空格后总 token 数与 v5 相当或更短 |
| v6 格式改动引入**新**失败模式 | F2/F3 是新增的「模型要生成的行」，本身可能出错（如位数锚点数错）——沿用 12 轮方法论：插桩统计 + 错例反推 + 手工试探 |
| 灾难性遗忘 | `mix_ratio 0.3` 已在 v5 验证无退化 |
| 双模式输出（简短直答 vs 竖式） | 暂不做，接受 §10 已知代价；列为后续增强（1–2 位直答、3 位以上展开） |
| 与社区 checkpoint 行为差异 | token id 完全兼容，但数字切分分布不同；本模型为自用数学专用，无影响 |
| 评测盲区复发 | 评测集先按符号/位数/接近度/写法做反向统计找 0 格（§8 检查 11），再开训 |
